# MVP 运行手册

> 2026-08-03 已完成 v1 smoke 全流程、v2 修复回归和 pilot 规模吞吐校准。
> 当前配置已升级为 `tcmi_scene_graph_v2`；v2 数据与审计已通过，训练链路尚未运行。
> 以下长时间命令由用户在 PowerShell 中执行。
> 长时间 pilot 训练前，必须先完成 smoke、查看预算和确认协议选择。

## 1. 进入项目

```powershell
Set-Location -LiteralPath '<克隆后的仓库目录>'
```

## 2. 创建环境并安装

先确认当前 `python` 是项目支持的 3.11 或 3.12：

```powershell
python --version
python -c "import sys; assert (3, 11) <= sys.version_info[:2] < (3, 13), sys.version"
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -e '.[dev]'
```

终端显示 `(base)` 只表示 Conda base 已激活。它可以提供兼容的 3.11/3.12
解释器来创建 `.venv`，但运行脚本仍只使用项目内的
`.venv\Scripts\python.exe`，不会静默复用 base 环境。若版本检查显示 3.13，需先切换到
3.11 或 3.12；本项目的 `pyproject.toml` 明确要求 `>=3.11,<3.13`。

安装后确认 PyTorch 能看到目标 GPU：

```powershell
.\.venv\Scripts\python.exe -c "import torch; print(torch.__version__); print(torch.cuda.is_available()); print(torch.cuda.get_device_name(0) if torch.cuda.is_available() else 'CPU only')"
```

若输出 `CPU only`，不要开始 smoke 或 pilot 训练，应按 PyTorch 官方安装器为本机 CUDA
环境安装对应 wheel。安装后必须重新执行上面的检查，确认输出 RTX 4090 和
`torch.cuda.is_available() == True`。

## 3. 先执行代码质量与测试

```powershell
.\.venv\Scripts\python.exe -m ruff check .
.\.venv\Scripts\python.exe -m pytest
```

完成标准：

- ruff 无错误；
- pytest 全部通过；
- 测试只在临时目录生成微型数据；
- 项目 `artifacts/` 与 `artifacts_v2/` 中没有被测试误写的运行产物。

当前默认训练契约为 `data_backend: gpu_resident`、`precision: fp32`、`tf32: false`。这些字段
会进入配置哈希；正式运行前若修改，必须重新做吞吐和公平预算核对。

## 4. smoke 数据与审计

当前命令生成 v2 数据并写入 `artifacts_v2/`。旧 `artifacts/` 是 v1 缺陷诊断证据，禁止
删除、覆盖或混入新版聚合。

```powershell
.\.venv\Scripts\python.exe -m tcmi generate --config configs\mvp_smoke.yaml
.\.venv\Scripts\python.exe -m tcmi audit --config configs\mvp_smoke.yaml
.\.venv\Scripts\python.exe -m tcmi status --config configs\mvp_smoke.yaml
```

预期：

- `audit_report.json` 的 `status` 为 `passed`；
- `oracle_audit.linear_decodability` 中 entity 与 joint_graph 均为 `1.0`；
- 四个条件的 latent digest 完全一致；
- oracle audit 通过；
- 此时仍没有训练结果。

数据集目录名由配置哈希决定；`heldout_modulus` 于 2026-08-04 由 5 改为 4（均衡排除规则，
见 D-MVP-20），旧哈希目录（smoke `...__2999e07bcae3`、审计失败的 pilot
`...__654a4867e72a`）保留为证据，不删除。脚本会拒绝覆盖既有 dataset；重新生成必须使用
新的配置哈希或归档目录。

## 5. 查看完整 smoke 命令矩阵

```powershell
.\.venv\Scripts\python.exe -m tcmi matrix --config configs\mvp_smoke.yaml --print-only
```

## 5.1 冻结前吞吐校准（已完成，可复核）

在 RTX 4090 上按 pilot 模型规模复核训练步速时运行：

```powershell
.\.venv\Scripts\python.exe scripts\throughput_calibration.py --config configs\mvp_pilot.yaml
```

脚本只测量工程吞吐，不生成训练 checkpoint，也不构成研究证据。当前校准记录显示 pilot
训练矩阵 fp32 外推约 3.08 GPU 小时；正式运行仍以各目录的 `budget.json` 为准，并包含
probe 时间和实际停止行为。

## 6. 执行 smoke

可一次执行：

```powershell
.\scripts\run_mvp.ps1 -Profile smoke -Stage all
```

脚本会先检查项目 `.venv` 和配置文件。任一 Python 子命令返回非零退出码时，当前阶段
立即停止，不会继续执行后续审计、聚合或裁决命令。

也可分阶段执行：

```powershell
.\scripts\run_mvp.ps1 -Profile smoke -Stage train
.\scripts\run_mvp.ps1 -Profile smoke -Stage probe
.\scripts\run_mvp.ps1 -Profile smoke -Stage aggregate
```

开始 `train` 前再次确认 CUDA；`training.device: auto` 会在 CUDA 不可用时选择 CPU，不能把
这种运行计入 RTX 4090 吞吐或 GPU 预算证据。

pilot 默认将每个条件的训练 split 驻留到 GPU。开始训练前确认显存足以容纳单条件数据和模型；
若要切回 `dataloader` 做诊断，必须保留新的配置哈希，并把该运行视为单独的工程校准，不得
与默认 pilot 矩阵混合聚合。

训练结束后必须先核对 run manifest、checkpoint、预算和源码状态。进入 probe 前，工作树
应位于包含 probe provenance 与预算聚合修复的干净提交；新 probe manifest 会单独记录评估
提交，并继续关联原训练提交和 checkpoint SHA-256。

smoke 完成标准：

- 所有 run manifest 为 `completed`；
- 每个配置 cell 都有三个 representation scope 的 probe；
- aggregate manifest 显示矩阵完整；
- `decision.json` 必须仍为 `experimental_in_progress`；
- smoke 数值不能用于研究结论。

v2 smoke 还必须检查：

- complementary entity 与 joint_graph 的主 scope 都是 fused；
- joint_graph probe 使用 4 类输出；
- 新 manifest 的 schema 为 `tcmi_scene_graph_v2`；
- 所有结果路径位于 `artifacts_v2/`。

## 7. pilot 数据与审计

仅在 smoke 完成后执行：

```powershell
.\.venv\Scripts\python.exe -m tcmi generate --config configs\mvp_pilot.yaml
.\.venv\Scripts\python.exe -m tcmi audit --config configs\mvp_pilot.yaml
.\.venv\Scripts\python.exe -m tcmi status --config configs\mvp_pilot.yaml
```

## 8. pilot 训练

这是长时间 GPU 流程，应由用户启动：

```powershell
.\scripts\run_mvp.ps1 -Profile pilot -Stage train
```

训练过程中另开 PowerShell 查看状态：

```powershell
.\.venv\Scripts\python.exe -m tcmi status --config configs\mvp_pilot.yaml
```

代码会累计已完成运行的 GPU 时间；达到 48 小时时会在 epoch 边界停止后续训练，并把失败运行预算写入磁盘。

## 9. pilot probe、聚合与裁决

训练矩阵完成后执行：

```powershell
.\scripts\run_mvp.ps1 -Profile pilot -Stage probe
.\scripts\run_mvp.ps1 -Profile pilot -Stage aggregate
```

预期裁决仍是 `experimental_in_progress`，因为配置证据等级为 `pilot`、协议状态为 `draft`。

## 10. 生成环境锁

确认环境可用后，在进入 formal 前生成并提交环境锁。若采用 `uv`：

```powershell
.\.venv\Scripts\python.exe -m pip install uv
uv lock
```

不得手工伪造 `uv.lock`。正式运行还需把协议状态、formal seeds 和全部机器可读阈值冻结在独立提交中。

usable-information / `I_V` 测量属于叙事升级草案的后续工作。它尚未实现或冻结，不能在
当前 smoke/pilot 报告中写成已有结果；若采纳，须在 pilot 后、formal 前单独冻结 probe 族和
事前预测表。

## 11. 重跑规则

代码默认拒绝覆盖既有 dataset、run、probe 和 aggregate 目录。发生失败时：

1. 先保留失败目录及日志；
2. 在缺陷文档记录原因；
3. 修改配置或代码；
4. 使用新的配置哈希、seed 或归档后的新输出目录重跑；
5. 不删除失败结果后假装首次成功。
