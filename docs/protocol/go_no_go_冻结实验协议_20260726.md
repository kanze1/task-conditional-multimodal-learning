# Go/No-Go 冻结实验协议

> 状态：草案，尚未冻结
> 日期：2026-07-26
> 最近修订：2026-08-02，`tcmi_scene_graph_v2` 互补任务与线性 probe 几何修复
> 适用阶段：两周最小验证
> GPU 预算上限：48 小时，单张 RTX 4090

## 1. 唯一生死判断

判断多模态相对单模态的结构表征增益，是否随任务条件信息结构发生稳定、方向正确且超出随机波动的变化。

本阶段不以最高单点分数、新方法增益或自然数据 benchmark 数量作为 Go/No-Go 依据。

## 2. 预注册实验因子

### 2.1 信息条件

1. `redundant`
2. `complementary`
3. `irrelevant`
4. `conflict`

所有条件必须共享潜在图分布，只允许改变预注册的模态投影变量。

### 2.2 训练条件

1. `image_only`
2. `text_only`
3. `multimodal_aligned`
4. `multimodal_shuffled`
5. `multimodal_conflict`

第一阶段主要统计冻结后的 image representation；文本表示只作对称补充。

### 2.3 结构任务

1. 实体；
2. 谓词；
3. 方向；
4. 联合图属性。

互补条件的两个预注册主任务为 entity 与 joint_graph，均使用 fused scope。predicate 与
direction 使用 image scope，承担任务分项与边界检查，不计入“两项互补任务”门槛。

### 2.4 架构与 seed

- 两种轻量架构，且归纳偏置不同；
- Go/No-Go 使用三个预注册 seed；
- 通过后正式验证扩展为五个 seed。

具体架构、参数规模与 seed 数值在协议冻结前补齐。冻结后不得依据结果更换。

## 3. 数据协议

- 训练集 50,000；
- 验证集 5,000；
- 测试集 5,000；
- 从潜在场景图确定性生成视觉和文本投影；
- 生成版本必须记录 schema 版本、seed、配置哈希和内容摘要；
- 必须验证标签可辨识性、投影条件、不变量、样本去重及划分隔离；
- CPU 环境必须能够复跑生成器审计。

## 4. 公平预算协议

必须同时记录并核对：

- encoder 与 fusion 部分参数量；
- 可训练参数量；
- 样本数；
- optimizer update 数；
- 图像编码次数；
- 文本 token 数；
- 总编码 token 预算；
- wall-clock 与 GPU 时间。

主比较必须保持目标模态 encoder、数据量与更新预算一致。若无法同时严格匹配参数量与计算量，必须预注册主匹配维度，并用第二种匹配方式做敏感性分析。

## 5. 主要指标

1. 冻结 encoder 的线性 probe accuracy；
2. unseen-combination accuracy；
3. conflict-flip accuracy；
4. missing-modality / corruption robustness；
5. 多模态相对 `image_only` 的增益：

   \[
   \Delta_k(c)=P_k(\text{multimodal},c)-P_k(\text{image_only})
   \]

主要统计对象为 `训练方式 × 信息条件 × 结构任务` 的交互效应。

主 scope 映射固定为：

- entity：fused；
- joint_graph：fused；
- predicate：image；
- direction：image。

## 6. Go / 大改 / No-Go

### 6.1 Go

必须同时满足：

1. `complementary` 下，多模态在 entity 与 joint_graph 两个预注册互补任务上均稳定优于 `image_only`，均值增益不少于 5 个百分点；
2. 增益超过三 seed 合并标准差的两倍；
3. `irrelevant` 下收益显著缩小，`conflict_flip` 下出现可重复退化；
4. 两种 encoder 归纳偏置下效应方向一致；
5. `shuffled`、参数量和更新预算控制不能解释结果。

### 6.2 大改

- `complementary` 有增益，但只在一个任务或一个架构出现；
- 冲突效应明显，但互补收益不稳定；
- 线性 probe 有收益，但 OOD/组合迁移不提升。

只能缩小命题，不进入自然数据大实验。

### 6.3 No-Go

任一情况成立即停止当前主线：

1. `complementary` 与 `irrelevant` 的增益无法区分；
2. 效应小于 2 个百分点且处于 seed 波动内；
3. shuffled caption 获得与有效 caption 相同的提升；
4. 结果主要由多模态模型参数量或训练 token 数解释；
5. 改变架构后效应方向翻转。

## 7. 证据等级

- `smoke`：只验证代码路径，不进入统计和结论；
- `pilot`：用于排错、估算资源和冻结协议，不作为正式证据；
- `formal`：协议冻结后按预注册矩阵运行，可进入 Go/No-Go 裁决。

任何结果目录都必须显式记录证据等级。smoke 与 pilot 不得被聚合进 formal 表格。

## 10. MVP pilot 实现选择

> 以下选择用于运行前的 MVP 代码搭建，不等同于正式预注册。

### 10.1 候选架构

- `tiny_vit`：4×4 patch 的小型视觉 Transformer；
- `tiny_cnn`：三阶段卷积 encoder；
- 两者使用相同宽度的文本 Transformer 和相同 embedding 维度；
- 主比较只在同一 architecture 内进行，跨 architecture 只检查效应方向。

### 10.2 pilot seed

- `2601`
- `2602`
- `2603`

这些是 pilot 默认值，不自动升级为 formal seed。

### 10.3 潜在图与标签

- `subject_shape ∈ {0,1,2,3}`；
- `object_shape ∈ {0,1,2,3}`；
- `predicate ∈ {0,1,2,3}`；
- `direction ∈ {0,1}`；
- `visual_key ∈ {0,1}`；
- `text_key ∈ {0,1}`；
- `joint_graph = 2 * visual_key + text_key`，为四分类联合状态；
- entity 标签为有序 subject/object shape 对，共 16 类。

训练集排除预注册哈希规则命中的 entity–predicate 组合，验证和测试各保持 seen/unseen 近似各半。

### 10.4 严格互补的表示边界

`complementary` 中两个主任务都按因子拆分：

- entity：image 暴露真实 subject shape，object shape 使用独立 nuisance；text 暴露真实
  object shape；
- joint_graph：image 暴露 `visual_key`，text 暴露 `text_key`；
- predicate 与 direction 在 image/text 中均真实可见，作为标准图文 InfoNCE 的共享对齐
  锚点；它们在 complementary 条件下属于任务条件冗余；
- 两个单模态都只携带部分目标信息，联合输入恢复完整标签；
- entity 的 16 类 pair 和 joint_graph 的 4 类 pair 都能由拼接 one-hot 上的多类线性
  分类器精确解码。

因此：

- entity 与 joint_graph 的互补性主检查必须使用 `fused` 表示；
- predicate、direction 继续报告冻结 `image` 表示；
- 不允许把 fused probe 的增益表述成 image encoder 单独获得了不可见信息；
- 所有任务同时输出 `image`、`text`、`fused`，用于揭示任务条件性。

### 10.5 v1 smoke 缺陷与证据隔离

2026-08-02 完成的 v1 smoke 使用二分类 XOR joint_graph。该目标无法由独立双塔表示的
拼接线性 probe 系统性解码；同时，v1 complementary 只有一个互补主任务，与“两任务”
Go 门槛不一致。v1 产物保留在 `artifacts/` 作为缺陷记录，不进入 v2 聚合。

v2 使用 `tcmi_scene_graph_v2`，输出到 `artifacts_v2/`。v2 数据审计必须同时验证离散
oracle 可辨识性和两个互补主任务的固定线性分类器准确率为 100%。

### 10.6 预算匹配控制

`image_only_matched` 将每个 batch 对半：

- 一半样本执行两个图像增强视图；
- 一半样本执行两个文本 dropout 视图；
- 合计图像编码次数、文本序列次数、optimizer update 和 trainable parameter 数与 aligned 条件匹配；
- 两个单模态 loss 相互独立，不产生跨模态梯度。

严格 `image_only` 仍保留为语义纯净基线，并单独报告其不同的编码预算。

### 10.7 当前证据门禁

- `mvp_smoke.yaml` 只能产生 `smoke`；
- `mvp_pilot.yaml` 只能产生 `pilot`；
- 协议状态为 `draft` 时，配置加载和运行入口都会拒绝 `formal`；
- pilot 裁决固定为 `experimental_in_progress`；
- formal 还要求 Git 工作树干净、完整矩阵、公平预算通过和累计不超过 48 GPU 小时。
