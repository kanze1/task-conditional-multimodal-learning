## D-MVP-1：严格互补与 image-only 主指标存在逻辑边界

若 `joint_graph` 的一部分只存在于文本，冻结 image representation 不可能单独恢复该独立信息。当前实现将 joint_graph 的互补主检查放在 fused scope，并继续对 entity、predicate、direction 报告 image scope。

正式协议仍需确认这一主指标映射。不得把 fused 增益写成 image encoder 获得了不可见信息。

## D-MVP-2：架构与 seed 仅为 pilot 默认值

`tiny_vit` 和 `tiny_cnn` 已在 smoke seed 2601 上完成训练并核对参数与预算。pilot 的
`2601/2602/2603` 三 seed 稳定性仍未运行，也未冻结为 formal。

## D-MVP-6：自动 Go 判定故意不完整

当前裁决器能检查证据等级、协议状态、矩阵完整性、预算和部分 complementary 阈值，但 irrelevant 显著缩小、shuffled 控制和 conflict-flip 的最终统计定义尚未机器可读化。因此即使未来误用 formal 标签，也不会自动宣告 Go。

## D-MVP-8：首次运行暴露 Windows 启动前检查问题

2026-07-31 的首次调用确认了三个启动层问题：

- 项目 `.venv` 尚未创建；当前 Conda base 的 Python 3.12.8 可作为创建它的解释器，
  但 `py` 启动器仅注册了不受项目支持的 Python 3.13；
- 旧脚本包含无 BOM 的 UTF-8 中文异常文本，在部分 Windows PowerShell 配置中显示为乱码；
- 旧脚本未显式检查原生 Python 进程的退出码，在 Windows PowerShell 5.1 中存在失败后继续
  执行同阶段后续命令的风险。

脚本已改为纯 ASCII 启动错误信息、明确的 3.11/3.12 环境创建指引、配置存在性检查和
逐命令退出码门禁。后续项目环境创建、测试、数据生成与审计已验证该启动路径可用。

## D-MVP-9：当前 PyTorch 环境不支持 CUDA（已解决）

初始环境为 `torch 2.13.0+cpu`。现已替换为 `torch 2.12.1+cu130`，CUDA 13.0 可用并识别
RTX 4090；40 个训练 run 的环境快照均确认该状态。

## D-MVP-10：editable install 元数据污染工作树状态

`pip install -e '.[dev]'` 在 `src/` 下生成
`task_conditional_multimodal_learning.egg-info/`，此前未被 `.gitignore` 覆盖，导致工作树
出现无关未跟踪文件。现已增加 `*.egg-info/` 规则；该目录保留为本地环境元数据，不进入 Git
或运行源码哈希范围。

## D-MVP-11：预算聚合读取错误的 evidence_level（已解决）

训练 manifest 把 `evidence_level` 放在顶层，而旧 `_audit_budgets` 错误读取
`manifest["identity"]["evidence_level"]`。该分支此前没有被实际 manifest 结构测试覆盖，
会使完成 probe 后的 aggregate 以 `KeyError` 失败。现已改读顶层字段，并新增真实形状的
预算公平性回归测试；对现有 40 个 run 的只读复核得到 8 个 matched pair、0 个失败。

## D-MVP-12：probe 未独立记录评估源码来源（已解决）

训练 run 记录训练提交，但旧 probe manifest 仅记录 scope、状态和结果路径。若训练后修复
评估代码，结果无法直接确定使用了哪个评估提交。新 probe manifest 和 metrics 会同时记录
评估源码状态、完整配置哈希、数据 manifest 哈希、协议哈希、训练提交和 checkpoint SHA-256；
formal probe 继续强制 clean 工作树。

## D-MVP-13：训练中 checkpoint 预算不是最终快照

已完成的 40 个 smoke checkpoint 在计时器停止前保存，因此内部
`budget.gpu_time_seconds` 为 `null`；权威 `budget.json` 与 run manifest 则在计时结束后写入，
二者完整一致，现有训练预算仍可审计。训练流程已改为停止计时后保存最终 checkpoint，保证
后续 pilot/formal 的最终 checkpoint 携带完整预算。现有 smoke checkpoint 不回写，以保留
原始证据；probe 通过 checkpoint SHA-256 绑定它们。
