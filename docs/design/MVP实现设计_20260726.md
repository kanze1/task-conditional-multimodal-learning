# MVP 实现设计

> 状态：v1 smoke 已完成；v2 数据与审计已通过，训练链路待运行验证
> 日期：2026-07-26
> 最近更新：2026-08-03
> 证据等级：默认 `smoke` / `pilot`

## 1. 目标

MVP 只验证受控信息条件是否能形成方向可预测的表示差异，不引入新 loss、新 fusion architecture 或 GCL。训练目标采用标准对比学习：

- 图像单模态：两个轻噪声视图的对比；
- 文本单模态：两个 token dropout 视图的对比；
- 多模态：图像—文本对比；
- shuffled：batch 内错配文本；
- conflict：训练文本与潜变量对齐，测试文本系统性翻转。

## 2. 数据契约

每个样本由相同潜在 `SceneGraph` 生成四个条件投影。sample ID、标签、split 和潜变量跨条件完全一致，只改变预注册的图像/文本可见性。

### 2.1 图像投影

- shape 编码 ordered entity；`complementary` 中图像保留真实 subject，object
  替换为由独立 `scene_nonce` 决定的 nuisance shape；
- relation line 编码 predicate；
- arrow direction 编码 direction；
- 左下 key patch 编码 `visual_key`；
- 除 `complementary` 外，右下 key patch 编码 `text_key`。

### 2.2 文本投影

固定 14 token、六个槽位，所有条件长度完全一致：

- `redundant`：六个槽位均为真实值；
- `complementary`：`object` 与 `text_key` 提供互补目标因子，predicate 与 direction
  作为图文共享对齐锚点，subject 与 visual_key 为独立 nuisance；
- `irrelevant`：全部为独立 nuisance；
- `conflict`：train/validation 为真实值，test 系统性置换或翻转。

### 2.3 数据产物

```text
artifacts_v2/data/<dataset_id>/
├── manifest.json
├── audit_report.json
└── <condition>/
    ├── manifest.json
    ├── sample_preview.jsonl
    ├── train/shard_*.npz
    ├── validation/shard_*.npz
    └── test/shard_*.npz
```

## 3. 训练契约

每个 run 目录由 `evidence + architecture + train_mode + condition + seed` 唯一确定，存在时拒绝覆盖。

```text
artifacts_v2/runs/<run_id>/
├── resolved_config.json
├── run_manifest.json
├── parameter_audit.json
├── budget.json
├── events.jsonl
├── checkpoints/epoch_*.pt
└── probes/<scope>/
    ├── probe_metrics.json
    └── failure_examples.jsonl
```

checkpoint 必须包含 config hash、dataset manifest hash、run identity 和预算快照。

### 3.1 训练后端与数值设置

- v2 配置默认使用 `training.data_backend: gpu_resident`：一个 `(condition, split)` 的
  全部 shard 在训练开始时加载为设备张量，按 seed 化 `randperm` 形成 batch；
- `gpu_resident` 与原 `DataLoader(shuffle=True, drop_last=True)` 保持样本数、batch 数和
  更新语义一致，但不承诺逐位相同的样本顺序；后端选择必须写入 resolved config 和配置哈希；
- v2 默认 `training.precision: fp32`、`training.tf32: false`。`bf16` 只保留为吞吐敏感性
  校准选项，不进入当前默认实验；
- GPU 驻留后端的 pilot 规模显存占用和训练步速由 `scripts/throughput_calibration.py`
  单独记录。吞吐校准是工程预算证据，不是研究结果。

## 4. 评估契约

冻结 encoder 后分别抽取：

- `image`；
- `text`；
- `fused = concat(image, text)`。

对 entity、predicate、direction、joint_graph 分别拟合线性 classifier，并输出：

- clean accuracy；
- unseen-combination accuracy；
- noisy image/text；
- missing image/text；
- conflicting text；
- 高置信失败样例。

`tcmi_scene_graph_v2` 的互补主任务与主 scope 固定为：

- `entity`：16 类 `(subject_shape, object_shape)`，fused scope；
- `joint_graph`：4 类 `2 * visual_key + text_key`，fused scope；
- `predicate`、`direction`：image scope，用于任务分项和非互补边界检查。

entity 与 joint_graph 的 fused 离散特征都是两个 one-hot 块的拼接，四类或十六类
目标可以由多类线性分类器精确解码。数据审计会机械验证这一几何性质。

标准 image–text InfoNCE 还要求正样本具有共享信息。complementary 图文共同暴露 predicate
和 direction；这两个变量对各自任务属于冗余信息，同时为 entity/joint_graph 的拆分投影
提供配对锚点。

## 5. 聚合与裁决

聚合器只读取与当前配置 evidence level 一致的结果，输出：

- `seed_metrics.csv`；
- `summary.csv`；
- `deltas.csv`；
- `interaction_summary.csv`；
- `multimodal_gain_by_condition.png`；
- `budget_and_fairness_audit.json`；
- `manifest.json`。

配置为 `smoke` 或 `pilot`、协议未冻结、矩阵不完整、预算超限或公平性缺失时，裁决器不能输出 Go。

## 6. v1 到 v2 的证据隔离

- v1 使用二分类 XOR joint_graph，和独立双塔拼接后的线性 probe 几何不相容；
- v1 complementary 只有 joint_graph 一个互补任务，无法满足“两任务”Go 门槛；
- v1 smoke 保留在 `artifacts/` 作为缺陷发现证据；
- v2 schema 为 `tcmi_scene_graph_v2`，输出根目录为 `artifacts_v2/`；
- v1 数值不进入 v2 聚合、pilot 或 formal 证据。

## 7. 明确限制

- v2 数据生成与机械审计已运行并通过，但训练、probe、聚合和裁决尚未运行，不能确认数值敏感性；
- 当前离散 oracle 用于验证生成投影，不是高维 PID 估计；
- synthetic MVP 不能承担自然数据或预训练 VLM 主张；
- 48 GPU 小时门禁使用 CUDA event，缺失时保守回退到 wall-clock；
- 正式环境锁需在依赖解析后生成并提交。
- usable-information / `I_V` 测量仍是叙事升级草案中的后续模块，未进入当前 MVP 运行链路；
  若采纳，必须在 formal 前另行冻结 probe 族与预测表。
