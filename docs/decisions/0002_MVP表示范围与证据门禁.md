# 决策 0002：MVP 表示范围与证据门禁

> 状态：v2 smoke 采用，formal 待冻结
> 日期：2026-07-26
> 修订：2026-08-03

## 决策

1. 同时评估 `image`、`text`、`fused` 三种冻结表示。
2. entity 与 joint_graph 的互补条件增益主视图使用 fused scope。
3. predicate 与 direction 的主视图使用 image scope。
4. `image_only_matched` 采用无跨模态梯度的 batch 对半双单模态控制。
5. smoke/pilot 配置不能生成 formal 结果。
6. 自动裁决在全部阈值机器可读化前不能宣告 Go。
7. GPU 驻留、fp32 与 TF32 开关属于配置和预算审计契约，不改变表示 scope 或 Go/No-Go 阈值。

## 原因

严格协同信息若只在联合输入中可辨，就不能要求 image encoder 在没有文本时恢复独立 text key。将表示范围显式分开，可以避免把融合收益错误解释为目标模态表征收益。

v1 smoke 进一步表明，二分类 XOR 无法由独立双塔表示的拼接线性解码。v2 因此把
joint_graph 注册为四分类 `(visual_key, text_key)` 联合状态，并把 entity 注册为
`(subject_shape, object_shape)` 的第二个互补任务。两者都保留严格的模态条件信息增量，
同时与冻结线性 probe 的表示几何一致。

## 后果

- 主结果必须标明 representation scope；
- delta 的 image-only baseline 与目标 scope 必须在聚合中显式记录；
- task 到主 scope 的映射已经在代码与协议中固定；formal 前仍需冻结交互统计模型；
- 新颖性叙事升级草案可以补充 usable-information 预测，但不能把尚未实现的 `I_V` 或预测表
  写成当前证据，也不能绕过现有 evidence gate。
