# Pilot 结果报告：任务条件多模态信息价值

> 日期：2026-08-04 ｜ 证据等级：**pilot**（协议 draft，不构成正式证据）
> 数据集：`controlled_scene_graph_mvp__tcmi_scene_graph_v2__71abe01cc3f3`（均衡 held-out 规则，审计通过）
> 矩阵：2 架构 × 6 训练模式 × 4 信息条件 × 3 seed = 120 训练 run + 360 probe，7080/7080 指标单元完整
> 预算：13.77 / 48 GPU 小时（RTX 4090，公平性审计通过，24 个 matched pair 无失败）

## 一、核心问题

多模态相对单模态的表征增益，是否随任务所需信息在模态间的分布结构（冗余 / 互补 /
无关 / 冲突）发生稳定、方向正确、超出 seed 波动的变化？

## 二、主要结果（complementary 条件，fused scope，aligned − image_only）

| 预注册主任务 | tiny_cnn | tiny_vit | ≥5pp 门槛 | >2×seed 标准差 |
|---|---|---|---|---|
| entity（图出 subject / 文出 object） | **+43.7pp**（sd 1.1） | **+42.5pp**（sd 1.5） | 通过 | 通过（≈30×） |
| joint_graph（图出 visual_key / 文出 text_key） | −3.2pp（sd 3.4） | **−20.2pp**（sd 1.3） | 未通过 | vit 显著为负 |

控制条件全部按预期方向：irrelevant 下增益为负（−18 至 −28pp，无假阳性）；conflict-flip
下 joint_graph 稳定退化（−51 / −54pp）；shuffled caption 仅解释 entity 增益的小部分
（+5 / +13.5pp ≪ +43pp）；两架构效应方向一致。

## 三、关键发现：对比对齐会主动抹除模态独有信息

complementary joint_graph 各训练方式的绝对准确率（随机 0.25，单模态上限 0.5）：

| 训练方式 | fused | image | text |
|---|---|---|---|
| image_only（文本塔未训练） | **0.9995** | 0.50 | 0.50 |
| text_only | 0.9999 | 0.49 | 0.50 |
| multimodal_aligned | **0.46 / 0.28** | 0.40 / 0.27 | 0.30 / 0.26 |

未经对齐训练的编码器（甚至随机文本塔）拼接后可近乎无损解码两个 key；InfoNCE 对齐
训练后反而掉到远低于单模态上限。解释：对比目标只奖励跨模态共享的变量（对齐锚点
predicate/direction），统计上跨模态独立的 key 对配对无贡献，被表示学习当作噪声清除，
且图像塔内的 visual_key 同样被压抑。entity 的成功与 joint_graph 的被抹除构成同一机制
的两面：**多模态增益是任务条件的——取决于任务所需信息与跨模态相关结构的对齐关系。**

## 四、按预注册 rubric 的定位

严格按协议 §6（若此格局出现于 formal）：entity 满足 Go 标准 1/2/4/5，joint_graph 不满足
标准 1，落入 §6.2 **"大改"** 象限（增益只在一个任务出现）。但协议尚未冻结，pilot 的
职能正是据此定稿协议；joint_graph 为两架构三 seed 一致、机制可解释、有随机基线反衬的
真实负效应，是可报告现象而非失败实验。

## 五、工程记录（详见缺陷文档）

- D-MVP-20：旧 held-out 哈希规则边缘不均衡，pilot 审计首跑拦截，已换均衡规则并验证；
- D-MVP-21：probe 特征提取 DataLoader worker 崩溃（WinError 6），改单进程并新增训练/
  probe 断点续跑；264 个已完成 probe 全部复用；
- 启动脚本两项 Windows PowerShell 5.1 缺陷（stderr 警告误终止、红色噪声）已修复；
- 吞吐校准准确：训练矩阵实测约 3.5 小时 wall-clock，与 3.08 GPU 小时外推一致；probe
  为当前墙钟主项（约 1.8 分钟/probe，串行 CPU bootstrap）。

## 六、下一步（冻结协议前）

1. **边界条件变体（廉价 pilot）**：验证抹除效应的成因——提高 key 的感知显著性、或给
   两 key 引入弱跨模态相关，观察抹除是否消失；结论决定主张表述强度。
2. **协议冻结方案**：倾向将 Go/No-Go 重写为预注册的方向预测剖面（entity 正增益、
   joint_graph 负增益/抹除、irrelevant 负、conflict 退化——pilot 四项全部命中），
   并决定是否纳入 usable-information / I_V 剖面作为形式化工具。
3. 机械项：生成并提交 `uv.lock`；冻结 formal seed（不复用 2601/2602/2603）与全部
   机器可读阈值；formal 需 clean 工作树，预算余量充足（34+ GPU 小时）。
